SLIDE 3: AWS ARCHITECTURE
========================================================

This diagram shows the complete AWS architecture I deployed.

Starting from the top:
- Internet users connect through the Application Load Balancer on port 80
- The Load Balancer sits in front of our VPC with CIDR block 10.0.0.0/16
- Inside the VPC, we have two subnets in different availability zones: eu-west-1a and eu-west-1b
- These subnets contain two EC2 instances:
  * One running the Docker container with our web application
  * And a backup API instance
- Both EC2 instances connect to an RDS MySQL 8.0 database named myprojectdb
- Additionally, we have an S3 bucket for storage and multiple Security Groups protecting each layer

This architecture ensures high availability, security, and scalability.

SLIDE 7: DEPLOYMENT PROCESS
========================================================

The deployment followed five distinct phases:

PHASE 1: Infrastructure Deployment
CloudFormation template was uploaded and executed. The stack named "MyAWSProject" was created with all AWS resources including VPC, EC2, RDS, Application Load Balancer, and S3. This entire infrastructure deployment took only 5 to 8 minutes.

PHASE 2: Application Development
I created a Node.js application with Express server, integrated MySQL database connectivity, built RESTful API endpoints, and developed a professional frontend with a working contact form.

PHASE 3: Containerization
Built a Docker image using Node.js 18 Alpine base, installed all dependencies, configured port mapping from port 80 to 3000, and deployed the container with an automatic restart policy.

PHASE 4: Load Balancer Configuration
Configured listener rules for path-based routing where /api/* routes to the application, set up target groups, enabled health checks on the /health endpoint, and verified complete connectivity.

PHASE 5: Testing and Validation
Tested all API endpoints thoroughly, verified database connectivity, submitted multiple test forms, confirmed data persistence in the database, and validated complete end-to-end functionality.

SLIDE 8: SECURITY CONFIGURATION
========================================================

Security was a top priority throughout this project.

LOAD BALANCER SECURITY GROUP:
- Allows inbound traffic on port 80 from the internet for public HTTP access
- Allows all outbound traffic

EC2 SECURITY GROUP:
- Allows inbound SSH on port 22 for administration
- Allows inbound port 80 only from the Load Balancer Security Group
- Allows inbound port 3000 only from the Load Balancer Security Group
- Blocks all direct public access to the EC2 instances

RDS SECURITY GROUP:
- Allows inbound traffic on port 3306 only from the EC2 Security Group
- Database is completely isolated from internet access
- Deployed in private subnet for additional security

APPLICATION SECURITY:
- All SQL queries use parameterized statements
- CORS configuration implemented
- Connection pool limits set
- Input validation on all forms

NETWORK SECURITY:
- Private database access only
- Security group chaining for layered protection
- Multi-AZ isolation
- Complete VPC network segmentation

POTENTIAL Q&A PREPARATION
========================================================

Common Questions You Might Face:

Q: Why did you choose Node.js over other technologies?
A: Node.js offers excellent performance for I/O operations, has a vast ecosystem with npm, and works seamlessly with JSON APIs. The Express framework makes building RESTful APIs straightforward.

Q: What happens if one availability zone fails?
A: The Application Load Balancer automatically routes traffic to healthy instances in the other availability zone, ensuring zero downtime.

Q: How do you handle database backups?
A: RDS provides automated daily backups with 1-day retention. I can easily increase this to 7 days or more based on requirements.

Q: What about HTTPS/SSL?
A: The current implementation uses HTTP. In production, I would add an AWS Certificate Manager SSL certificate to the Load Balancer for HTTPS encryption.

Q: How would you scale this application?
A: I would implement Auto Scaling Groups for EC2 instances, use RDS Read Replicas for database scaling, and consider ElastiCache for caching frequently accessed data.

Q: What about monitoring and logging?
A: AWS CloudWatch can be configured for monitoring metrics, setting up alarms, and centralized logging. CloudWatch Logs would collect application and system logs.

Q: How long did the entire project take?
A: The infrastructure deployment takes 5-8 minutes. Application development and testing took several hours. Overall, from planning to completion: approximately 1-2 days of work.

Q: What would you do differently in production?
A: In production I would add:
- HTTPS with SSL certificates
- Auto Scaling Groups
- CloudWatch monitoring and alarms
- RDS Multi-AZ deployment
- More comprehensive logging
- CI/CD pipeline for automated deployments
- WAF (Web Application Firewall)
- Backup and disaster recovery procedures
